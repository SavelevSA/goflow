# План капитана на пять дней

На каждый день отводится 2–3 часа. Цель дня 3 — браузерный MVP. Цель дня 5 — воспроизводимая сборка и готовность к защите.

| День | Задачи капитана | Результат |
|---|---|---|
| 1 | Репозиторий и ветки, модели, JSON-контракт, проверка минимального go-app | Команда может начать работу по общему контракту |
| 2 | REST API, валидация, тесты обработчиков, подключение тестового состояния | GET и четыре POST можно проверять независимо от UI |
| 3 | Подключение движка и контроллеров, review веток, браузерная интеграция | Машины, светофоры и команды работают на одном сервере |
| 4 | Проверка ошибок, гонок, сброса, паузы и сравнения режимов | Сценарии воспроизводятся на одном seed |
| 5 | Чистая сборка, документация, сценарий демонстрации, репетиция | Проект готов к защите |

## День 1

| Время | Задача | Критерий готовности |
|---|---|---|
| 25 мин | Проверить Go/Git, подготовить репозиторий и первый коммит | У всех участников одинаковая версия Go, у репозитория есть `main` |
| 45 мин | Согласовать `types.go`, `simulation.go`, `docs/API.md` | У №2 и №4 совпадают имена полей, единицы и команды |
| 40 мин | Собрать WASM, запустить сервер, проверить кнопку и тестовый GET | Кнопка меняет текст, Snapshot приходит с четырьмя перекрёстками |
| 30 мин | Передать команде контракты, назначить ветки | У каждого участника есть стартовая задача |

## Сообщение для команды

Всем привет! Начинаем GoFlow. Используем Go 1.26.x и go-app `v11.0.5`. Перед началом напишите результат `go version`, чтобы выбрать одинаковую версию Go для всех. Общие типы лежат в `internal/model/types.go`, JSON и форматы команд — в `docs/API.md`. Сборка описана в `README.md`. Локальный адрес — `http://127.0.0.1:8080`.

- **№2, `feat/simulation`.** Создай каркас Engine в `internal/sim`. Начни с одного фонового цикла и четырёх перекрёстков. Сверь `Snapshot`, жизненный цикл и команды с `internal/api/simulation.go`.
- **№3, `feat/control`.** Согласуй с №2 сигнатуру контроллера. Подготовь интерфейс и первую версию Fixed в `internal/control`. На первой проверке покажи, что фазы меняются по заданному интервалу.
- **№4, `feat/ui`.** Собери WASM по README и добавь статическую схему 2×2 в `internal/ui`. Для запроса снимка используй относительный путь `/api/state`. Пример JSON есть в `docs/API.md`.

В конце дня пришлите название ветки, что получилось, какие проверки запускали и что мешает двигаться дальше. Цель к концу дня 3 — открыть браузерный MVP с движением машин и командами управления.
